## Блок 1. Как читать небольшую программу

Имя переменной связывается со значением. `=` выполняет присваивание. Кавычки обозначают строку; число без кавычек — другой тип данных. `print(...)` выводит значение для наблюдения, но сам вывод не является возвращаемым значением твоей функции.

Функция описывает повторяемое действие. `def` начинает определение, параметры находятся в скобках, после заголовка стоит двоеточие. Отступом обозначается тело. `return` завершает вызов и передаёт результат вызывающему коду.

Разобранный пример:

```python
fee = 3

def total_items(boxes: int, per_box: int) -> int:
    result = boxes * per_box
    return result

count = total_items(4, 6)
print(count)
print(fee)
```

Сначала создаётся `fee`. Затем определяется функция, но её тело ещё не выполняется. Вызов передаёт `4` в `boxes`, `6` в `per_box`. Локальная `result` получает `24`, это значение возвращается и связывается с `count`. Вывод — строки `24` и `3`. Локальные параметры и `result` относятся к вызову функции, а не становятся автоматически глобальными переменными.

`int` и `-> int` — аннотации для читателя, анализаторов и инструментов. Они сами по себе не выполняют проверку всех аргументов во время вызова. Проверки границы будут отдельным шагом.

В ответе объясни, какая строка определяет функцию, какая вызывает её, что возвращается и чем параметр отличается от аргумента. Если термин мешает — сохрани именно этот вопрос.

## Блок 2. Данные, ветвления и коллекции

В наших задачах понадобятся `int` для целого числа, `str` для текста, `bool` для логического значения, `None` для явно выбранного отсутствия значения. Строка `"12"` и число `12` имеют разный смысл. Не превращай их друг в друга без решения о контракте.

`list` хранит последовательность, `dict` — соответствие ключей и значений. Доступ к словарю по отсутствующему ключу через `row["key"]` вызывает `KeyError`; `get` позволяет задать поведение при отсутствии. Это выбор программы, а не автоматическое исправление любых данных.

```python
rows = [{"category": "guide"}, {"category": "report"}]
labels = []
for row in rows:
    category = row.get("category")
    if category == "guide":
        labels.append("instructions")
    else:
        labels.append("other")
print(labels)
```

Цикл берёт словари по одному. Для первого выполняется ветка `if`, для второго — `else`. Новый список содержит `['instructions', 'other']`; сами словари здесь не изменяются. Пример намеренно не валидирует полную схему: на следующем блоке добавим явные ограничения.

## Блок 3. Изменяемость и контракт функции

Несколько имён могут ссылаться на один изменяемый объект. Новое присваивание имени не всегда означает создание новой коллекции. Это важно для общего состояния запросов, памяти агента и непреднамеренного изменения входа.

```python
original = ["guide"]
alias = original
separate = original.copy()
alias.append("report")
print(original)
print(separate)
print(original is alias)
```

`alias` и `original` ссылаются на один список. После `append` исходный список содержит два элемента. `separate` — отдельный список с одним элементом. Последний вывод — `True`. `copy()` здесь поверхностная: если внутри были вложенные изменяемые объекты, они могли бы остаться общими.

Контракт функции отвечает на четыре вопроса: что разрешено на входе, что возвращается, какие изменения состояния допустимы, как сообщается об ошибке. Например, преобразование заметок может возвращать новый список и отклонять неверный тип вместо молчаливого пропуска. В производственном коде важно не потерять ошибку, выдавая её за пустой успешный результат.

Имена исключений тоже часть объяснения: `TypeError` может обозначать неподходящий тип, `ValueError` — недопустимое значение подходящего типа. `try/except` ставят там, где можно содержательно обработать конкретный отказ. `except Exception: return []` смешал бы ошибку с корректным отсутствием записей. Пустой список по контракту и невозможность получить данные — разные состояния.

## Блок 4. Внешние данные: несколько отдельных проверок

Ответ внешнего сервиса проходит несколько границ:

- Транспорт: удалось ли установить соединение и получить ответ за допустимое время?
- HTTP: какой статус вернулся и что он означает для конкретного API?
- Формат: тело действительно разбирается как ожидаемый JSON?
- Схема: в полученной структуре правильные поля, типы и ограничения?
- Предметный смысл: имеет ли операция право выполняться и соответствует ли результат задаче?

Успех на одной границе не гарантирует успеха на следующей. Заголовок формата — утверждение отправителя, которое проверяют при разборе. Повтор после ошибки зависит от причины и от безопасности повторного эффекта, а не только от кода статуса. Для операций записи требуется отдельная стратегия идемпотентности; сетевой timeout сам по себе не доказывает, что запись не произошла.

JSON — текстовый формат обмена. После разбора получается объект Python. У него свои обозначения логических значений и отсутствия. Разбираем новый пример, который не является ответом D00:

```python
import json

payload = '{"document_id":"doc-7","pages":8}'
record = json.loads(payload)
print(type(record).__name__)
print(record["pages"] + 2)
```

Полученный объект — `dict`, второе наблюдение — `10`. Разбор формата ещё не установил, что `pages` всегда число: это проверяется схемой. Для журнала ошибки нужны код причины, стадия, безопасный request ID и длительность; токен, содержимое личного документа и необработанный текст исключения могут раскрыть данные. Разрешённые поля логирования лучше перечислить заранее.

## Блок 5. Pydantic и FastAPI: граница данных

Модель Pydantic описывает поля и ограничения; валидация превращает внешние данные в допустимую структуру либо сообщает о нарушении. Настройка `extra="forbid"` отклоняет неизвестные поля. Строгая проверка нужна там, где нежелательно приведение строки к числу. Допустимые преобразования выбираются явно.

```python
from pydantic import BaseModel, ConfigDict, Field, ValidationError

class DocumentRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    document_id: str = Field(min_length=1)
    pages: int = Field(ge=1)

valid = DocumentRequest.model_validate({"document_id": "doc-7", "pages": 8})
print(valid.pages)
try:
    DocumentRequest.model_validate({"document_id": "doc-7", "pages": "8"})
except ValidationError:
    print("schema rejected")
```

Первый вход проходит. Второй намеренно отклоняется: при выбранном строгом контракте строка не равна целому числу. Модель не доказывает, что документ существует и пользователь имеет к нему доступ — такие проверки выполняются отдельно.

FastAPI использует модели на границах запроса и ответа. Этот пример не запускает сервер и ничего не сохраняет:

```python
from fastapi import FastAPI
from pydantic import BaseModel, ConfigDict, Field

class DocumentRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    document_id: str = Field(min_length=1)
    pages: int = Field(ge=1)

class DocumentResponse(BaseModel):
    accepted: bool

app = FastAPI()

@app.post("/documents", response_model=DocumentResponse)
def create_document(body: DocumentRequest) -> DocumentResponse:
    return DocumentResponse(accepted=True)
```

Тело `body` проходит проверку схемы до обработки функцией. В настоящем проекте после неё добавятся права, предметные правила и запись состояния. Здесь `accepted=True` — учебная заглушка, не доказательство сохранения. В лабораторной понадобятся положительный и отрицательные запросы через тестовый клиент и проверки отсутствия эффекта при отказе.

## Блок 6. asyncio: что именно выполняется одновременно

`async def` определяет coroutine function. Её обычный вызов создаёт coroutine object, а не сам по себе запускает выполнение. `await` ожидает результат awaitable; при подходящей операции ожидания управление может получить другая задача. Для нескольких одновременных задач нужны их планирование и управление жизненным циклом.

Event loop выполняет задачи кооперативно. Блокирующее ожидание или тяжёлый синхронный код в том же потоке мешает другим задачам. Поэтому важно различать ожидание I/O и вычисления; один `async` перед определением не делает любое содержимое неблокирующим.

Пример с искусственным ожиданием, без сети и моделей:

```python
import asyncio

async def process_document(name: str, limit: asyncio.Semaphore) -> str:
    async with limit:
        await asyncio.sleep(0.01)
        return name.upper()

async def main() -> None:
    limit = asyncio.Semaphore(2)
    async with asyncio.timeout(1):
        async with asyncio.TaskGroup() as group:
            tasks = [
                group.create_task(process_document(name, limit))
                for name in ["guide", "report", "memo"]
            ]
    print([task.result() for task in tasks])

asyncio.run(main())
```

Semaphore допускает не больше двух задач в защищённую область. `TaskGroup` ждёт созданные задачи и управляет их завершением при ошибке. Общее окно `timeout` ограничивает время этой группы; при срабатывании возникает ошибка, которую обработчик верхнего уровня должен явно показать. В реальном клиенте дополнительно нужны транспортные таймауты.

Отмена — отдельный путь завершения, требующий освобождения ресурсов через контекстные менеджеры или `finally`. Нельзя проглатывать её и объявлять результат успешным. Для очень большого потока документов создавать сразу задачу на каждый элемент тоже дорого: тогда нужна ограниченная очередь/пул работников. Маленький пример выше не является такой очередью.

## Что сохранить после первого блока

Сначала достаточно одного блока. В форму ниже вставь:

```text
Блок: 1
Что я понял:
Мой код или алгоритм:
Прогноз перед запуском:
Наблюдение после запуска:
Что осталось непонятным:
Использованная помощь:
```

Пустые разделы можно объяснить: «код пока не запускал», «нужен разбор термина». Не выдавай готовый пример из материала за самостоятельное решение. Уверенность и самостоятельность — разные сведения.

После сохранения ответ появится в [истории обучения](/history). Если нужен разбор, можно сообщить в чат только «проверь мою запись на платформе»; сам разбор и следующее упражнение размещаются в платформе. До разбора не нужно переходить ко всем следующим блокам сразу. Самостоятельная проверка будет новым заданием после практики; освоение сейчас не увеличивается.

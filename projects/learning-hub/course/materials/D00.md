# D00 · Диагностика Python, HTTP, asyncio и JSON

Это первая самостоятельная попытка, а не экзамен на скорость. Предварительная оценка — 60–90 минут; фактическое время используется для настройки маршрута и ничего не гарантирует. Никаких запросов к модели и системных изменений не требуется. Эталонов здесь нет.

Сначала ответьте без подсказок. Отметьте у каждого пункта уверенность и происхождение: самостоятельно / документация / подсказка / сгенерировано AI. После фиксации первой попытки можно читать документацию и прислать отдельное исправление, сохранив исходное. «Не знаю» полезнее догадки без пометки. Не загружайте реальные персональные данные, токены и полные логи окружения.

## Задания

### Задание 1. Типы и изменяемость.
 Не запуская код, предскажите результат двух вызовов и объясните причину. Затем проверьте прогноз в Python и отдельно запишите фактический вывод.

```python
def collect(value, bucket=[]):
    bucket.append(value)
    return bucket
first = collect("a")
second = collect("b")
print(first, second, first is second)
```

### Задание 2. Контракт функции.
 Напишите `summarize(rows: list[dict]) -> dict[str, int]`: подсчитать записи по `status`; разрешены `open` и `closed`. Не менять вход. Для отсутствующего поля и недопустимого значения выбрать и описать явное поведение. Приведите четыре входа: нормальный, пустой, без `status`, с неверным типом. Объясните, где нужен `try/except`.
### Задание 3. HTTP.
 Клиент получил: (а) 200 с HTML, (б) 429 с JSON, (в) соединение не установлено, (г) 200 с `{"count":"many"}` вместо целого `count`. Для каждого укажите слой ошибки, что безопасно записать в журнал и допустим ли автоматический повтор. Чем `Content-Type` отличается от действительной валидности тела?
### Задание 4. JSON и схема.
 Разберите различия между `{"active":true}`, `{'active': True}` и `{"active":"true"}`. Какие строки являются JSON? Какая бизнес-схема нужна, чтобы не принять строку вместо булева? Где может возникнуть нежелательное приведение типа?
### Задание 5. asyncio.
 Что фактически произойдёт, если вызвать `async def fetch()` без `await`? Почему `time.sleep(2)` внутри coroutine мешает соседним задачам? Набросайте план обработки десяти запросов с лимитом два одновременно, timeout и отменой. Реализацию HTTP пока писать не нужно.
### Задание 6. Исключения.
 Функция ловит `Exception` и возвращает `{}` для любой ошибки. Назовите два случая, когда это вводит вызывающий код в заблуждение. Предложите контракт ошибок, сохраняя различие между отсутствием данных и неуспешным запросом.
### Задание 7. Pydantic/FastAPI.
 Опишите схему POST `/tickets`: `ticket_id` — непустая строка, `priority` — одно из `low|normal|high`, неизвестные поля запрещены. Какие проверки относятся к схеме, а какие требуют БД/прав пользователя? Дайте по одному отрицательному примеру.
### Задание 8. Воспроизводимость.
 Чем изолированное окружение отличается от глобальной установки пакета? Что требуется сохранить кроме `requirements` или lock-файла, чтобы другой человек повторил ваш эксперимент? Объясните роль `uv`, не устанавливая системные пакеты.
### Задание 9. Перенос.
 У сервиса генерации есть токен в окружении и текст резюме. Спроектируйте безопасную запись об ошибке без публикации токена и резюме. Как доказать, что повтор операции не отправит второй платёж?

## Что передать

Один ответ с нумерацией 1–9; код задания 2; прогноз и фактический результат задания 1; затраченное время; список использованных источников/помощи; три наиболее неясные темы. Для устной проверки будьте готовы изменить одну входную строку и объяснить последствия без генерации ответа AI.

## Как разбирается попытка

| Область | Наблюдаемое доказательство | Следующее действие при пробеле |
|---|---|---|
| Python | Предсказание отделено от запуска; функция имеет контракт и граничные случаи | Объяснение изменяемости, новый пример с другим контейнером |
| HTTP/JSON | Ошибки четырёх слоёв различены; предложен безопасный журнал | Разбор одного ответа и новый набор статусов |
| asyncio | Объяснены await, блокировка, лимит и отмена | Малый эксперимент с двумя coroutine |
| Схемы | Отличены формат, тип, права и предметный инвариант | Объяснение валидации и новый контракт |
| Среда | Можно описать повторение эксперимента без глобальных изменений | Работа с локальным окружением и версиями |

Диагностика не ставит автоматический зачёт M00. Проверяющий связывает конкретные свидетельства с O-M00-01…O-M00-05, отмечает неопределённость и предлагает точечное объяснение.

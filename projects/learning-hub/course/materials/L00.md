# L00 · Python, HTTP и прямой LLM API

Результат занятия: объяснить путь запроса, выбрать границу конфигурации и различать сетевую ошибку, JSON и предметную валидацию. Перед чтением сохраните [D00](D00.md). Предварительно 45–75 минут с упражнениями; это ориентир для первой итерации.

## От функции к запросу

Обычная Python-функция получает значение и возвращает результат в том же процессе. HTTP-клиент сериализует данные в байты, передаёт их серверу и ждёт ответа. Возникают дополнительные границы: адрес сервера, timeout, статус ответа, формат тела и доверие к его содержимому. Получить HTTP 200 недостаточно: тело может быть не JSON, а правильный JSON может нарушать предметный контракт.

SDK — библиотека клиента, а не модель. Официальный OpenAI Python SDK формирует запросы и объекты ответа; `AsyncOpenAI` позволяет ожидать сетевой I/O через `await`. Ollama — отдельный локальный сервер с моделью; его совместимый `/v1` endpoint позволяет применять тот же клиент к поддерживаемому подмножеству API. Настройки `base_url`, `api_key`, `model` не должны быть зашиты в предметную функцию. Эти роли и границы поддерживаются [документацией OpenAI Python SDK](https://developers.openai.com/api/reference/python) и [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility).

Смена адреса не доказывает одинаковые возможности. Для первого упражнения используем Chat Completions. Responses API изучается отдельным запланированным занятием M01: input/output, state, tools и streaming сравниваются по фактическим версиям. Полную совместимость Ollama с Responses, tool calling или structured outputs мы не предполагаем.

## Разобранный пример: локальные данные, без модели и сети

```python
import json
from collections import Counter

def count_events(raw: str) -> dict[str, int]:
    events = json.loads(raw)  # синтаксис JSON; неверная строка даст исключение
    if not isinstance(events, list):
        raise ValueError("ожидался список событий")
    if any(not isinstance(item, str) for item in events):
        raise ValueError("каждое событие должно быть строкой")
    return dict(Counter(events))

print(count_events('["read", "write", "read"]'))
```

`json.loads` превращает текст в Python-значения. Проверки после него задают наш контракт. `Counter` подсчитывает уже проверенные строки. Ввод `{"read":2}` синтаксически корректен, но нарушает контракт списка. Исключение не превращаем молча в пустой успешный результат. Этот пример демонстрирует слои данных; он не решает извлечение заявки из LAB01.

Теперь самостоятельно измените пример: разрешите только `read|write` и опишите поведение на неизвестное событие. Сначала сформулируйте контракт и два отрицательных входа, затем код. Разбор даётся после вашей попытки.

## Асинхронность и жизненный цикл

Вызов `async def` создаёт coroutine; `await` передаёт управление event loop на время ожидания. Это не превращает вычисления CPU в параллельные и не делает `time.sleep` неблокирующим. Для запроса важны общий deadline, закрытие клиента, отмена и ограничение конкурентности. В LAB01 достаточно одного запроса; очередь и retries с backoff появятся после наблюдения простого поведения. Не складывайте собственные retries поверх неучтённых повторов SDK.

План прямого вызова: прочитать и проверить конфигурацию → создать `AsyncOpenAI` с явными `base_url`, `api_key`, timeout и ограничением повторов → `await client.chat.completions.create(...)` → проверить непустой content → разобрать JSON → валидировать Pydantic → вернуть предметный объект → закрыть клиент. Реализацию этого плана выполняет ученик.

## Схема не равна истине

Pydantic проверяет структуру и заданные ограничения; он не удостоверяет, что модель правильно прочитала документ. Для LAB01 нужно самостоятельно описать `TicketExtraction`: `category` в `billing|technical|other`, `urgency` в `low|normal|high`, `summary` длиной 1–120 символов; лишние поля запрещены. Необходимость строгих типов и допустимые преобразования объясните отдельно. Метод `model_validate_json` объединяет разбор JSON с валидацией; для наблюдения слоёв можно явно разделить стадии. Основание — [Pydantic Models](https://docs.pydantic.dev/latest/concepts/models/).

Модель генерирует последовательность токенов, а не исполняет обещанный контракт. Токен не равен слову; ограниченный контекст вмещает инструкции, историю и документы. Температура меняет sampling и не гарантирует ни корректность, ни полную воспроизводимость. Математика вероятностей следующего токена, attention и векторного сходства включена в M01–M03; сейчас достаточно понять, почему ответ нуждается в проверке.

## Локальный режим и переключение

Локальный профиль: `http://127.0.0.1:11434/v1`, `qwen2.5-coder:7b`, фиктивный локальный ключ `ollama`. Бюджет внешних ресурсов — $0. Для локального режима блокируются внешние адреса и облачные модели. При дальнейшем переключении выбираются облачный профиль, реальный ключ и отдельно одобренный лимит; отсутствующее согласование означает отказ до сетевого вызова. Наличие ключа само по себе не разрешает трату. В первой лабораторной облачная ветка полностью закрыта.

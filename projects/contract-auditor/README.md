# Аудитор договоров

Выделяет структуру и проверяемые риск-флаги в учебных договорах с точными ссылками на положения.

Статус реализации: **planned**. Здесь паспорт будущего самостоятельного capstone, а не готовое приложение. Рабочей demo-команды пока нет: `demo_command` в паспорте имеет значение `planned`. Нельзя считать этот каталог пройденным проектом, использовать фиктивную команду запуска или засчитывать навыки по наличию README.

Канонический контракт — [passport.json](passport.json): пользователь, предметный workflow, учебные данные, baseline, уникальные результаты, skill IDs и наблюдаемые критерии приёмки. Эти поля связываются с [каталогом курса](../learning-hub/course/catalog.json); учебные результаты и свидетельства остаются отдельными сущностями.

Первый перенос доступен после M00–M02: описать контракт ввода/вывода и негативные случаи этого сценария. Затем — реализовать baseline до усложнения, собрать версионированный набор, выполнить эксперимент на тех же данных, добавить устойчивость/защиту/наблюдаемость, подготовить отдельную демонстрацию. Полная интеграция и независимая защита относятся к M08; углубления из M05–M07 подключаются по предпосылкам. Одинаковый общий компонент не заменяет уникальную предметную приёмку.

План приёмки берётся из `acceptance`: каждый пункт должен иметь воспроизводимый сценарий, ожидаемый эффект и фактическое свидетельство. Итоговый отчёт сравнивает baseline и AI-систему на одинаковом наборе, объясняет ошибки и ограничения. Ни готовность проекта, ни общий процент тестов не доказывают самостоятельное владение ученика; требуется новая задача и защита с фиксацией помощи. Оценки времени предварительны, сроки трудоустройства и рыночный результат не обещаны.

Только синтетические данные, локальный запуск по умолчанию и бюджет внешних ресурсов $0 до отдельного согласования. Изменение VPN, ядра, драйверов или системных пакетов не входит в проект.

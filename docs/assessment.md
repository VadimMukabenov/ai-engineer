# Попытки, оценка и следующий шаг

Первая попытка сохраняется через форму урока в `learning_records/attempts/attempt-<uuid>.json`. Исправление — новая попытка, исходную не перезаписывать. `assistance` фиксирует помощь, а не уверенность: none/documentation/hint/ai_partial/ai_solution.

После попытки попросить Codex «Сделай ревью D00». Проверяющий сначала читает попытку, урок и точные criteria результата из каталога, разбирает ошибку, даёт точечную теорию/упражнение. Для зачёта нужна новая независимая задача, перенос или устная защита. Сгенерированное ИИ решение само по себе не подтверждает навык; независимую проверку не проводить путём выдачи готового ответа.

Оценка записывается отдельным JSON в `learning_records/assessments/`, а доказательства — файлами внутри репозитория. Публичный Git: использовать синтетические данные, без личных сведений, чужих документов, production-логов или токенов. Перед публикацией просмотреть diff. Непубликуемые данные хранить приватно; не создавать в публичном каталоге записи, содержащие такие сведения.

Поля assessment (схема реализована `learning_hub.records.Assessment`):

- schema_version=1; уникальные id и совпадающее имя файла `<id>.json`;
- attempt_id и **attempt_sha256** — SHA-256 исходных bytes JSON оцениваемой попытки;
- course_version, outcome_id, criterion_version — точные версии, не текущая дата;
- decision: passed или needs_work; method: independent_task / transfer_check / oral_defence;
- reviewer, содержательная rationale, assistance, recorded_at с timezone;
- evidence: непустой список `{path, sha256}` реальных файлов. Файлы и hashes проверяются; содержание оценивает проверяющий.

Не ставить дату раньше фактической проверки, не копировать один положительный комментарий на все результаты. Освоение считается по уникальным outcome, отдельно от числа попыток; последняя оценка выбирается внутри актуальной версии критерия. Изменение попытки или доказательства после оценки обнаруживается. Зачёт старого критерия не переносится автоматически.

В первой версии оценка оформляется проверяющим через файл и review; отдельной кнопки «зачесть всё» и автоматического LLM-экзаменатора нет. После записи: `make verify`, `make status`, `make readme`. Убедиться, что изменилась именно ожидаемая часть прогресса. Затем сохранить проверенный diff в Git.

Начальный диагностический шаг записан в плане как D00. Он не перемещается автоматически при отправке формы: после разбора наставник формирует следующий конкретный шаг (точечное объяснение M00 либо L00 → LAB01), отражает его в Beads и CONTEXT. Это избегает перехода к новой теме только по факту отправки ответа.

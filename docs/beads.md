# Локальный Beads и переносимый snapshot

Этот репозиторий использует **Beads 1.0.3**, отдельную embedded Dolt базу `aie` в `.beads/embeddeddolt`. Обычный глобальный `bd` подключён к другому командному tracker и для курса не применяется. Wrapper вызывает только `Path.home() / ".local/bin/bd.real"`; на другом компьютере этот проверенный бинарник той же версии должен быть установлен по указанному пути или путь нужно явно пересмотреть в скрипте.

## Обычная работа

Из любого текущего каталога используйте абсолютный путь к `scripts/bd` этого checkout либо из корня:

```bash
scripts/bd context --json
scripts/bd ready
scripts/bd list --json
scripts/bd show aie-qg3
```

Команда должна идти первым аргументом, флаги — после неё. Wrapper выбирает корень по своему файлу, создаёт чистое окружение из allowlist, не наследует `BEADS_*`, `BD_*`, `DOLT_*`, Git routing и proxy variables. Пользовательский XDG config изолирован; global Git config отключён. HOME определяется по текущему OS-пользователю, а не наследуется из окружения: CLI считает некоторые пути небезопасными при фиктивном HOME. Контекст проверяется до работы с базой: `embedded`, `aie`, версия `1.0.3`, точное совпадение root/`.beads`, отсутствие redirect и symlink в основных путях. Серверный режим и shared server отключены, `--sandbox` отключает autosync.

`--global`, `--db`, database/backend/server/path overrides и команды init/import/config/remote/sql не проходят wrapper. Экспорт wrapper разрешает только в stdout; `-o/--output` отключены. Для переносимого сохранения используйте отдельную команду ниже. Обычные issue-команды создания/изменения разрешены для работы пользователя; при проверке этой основы статусы реальных задач не менялись. Read-команды wrapper запускает с `--readonly`.

Это проверка маршрутизации и защита от случайного выбора чужой базы. Владелец файлов может изменить wrapper или запустить другой бинарник напрямую; независимой границей прав он не является.

## Что сохраняем в Git

Используем реально доступные команды `bd export --all` и `bd import <file>`, а не неподдержанный псевдо-backup. Snapshot содержит:

- `issues.jsonl`: свежий полный экспорт из базы, включая закрытые задачи, типы, поля, labels, зависимости, комментарии и memories, поддерживаемые CLI;
- `manifest.json`: формат, версия CLI, время UTC, source project ID, SHA-256 JSONL, количество сущностей и ограничения round-trip.

`--readonly export --all` читает живую базу и не меняет статусы/комментарии. Не используем существующий `.beads/issues.jsonl` как доказательство свежести: auto-export имеет задержку и наблюдался без последних зависимостей. Snapshot создаётся в **новом** каталоге и не заменяет предыдущий.

Пример сохранения в Git-совместимый каталог; команды Git выполняет человек/основной рабочий процесс после просмотра diff:

```bash
mkdir -p backups
scripts/beads-portable snapshot --public backups/beads-2026-11-27-01
scripts/beads-portable verify backups/beads-2026-11-27-01
```

В Git следует добавлять только два файла snapshot и исходники/документацию. `.beads/embeddeddolt`, `.dolt`, lock/journal/chunks и другие сырые файлы БД не добавлять. Snapshot содержит тексты задач, авторов и комментариев; перед публикацией проверяйте содержимое и права целевого репозитория. Для публичного `VadimMukabenov/ai-engineer` обязателен `snapshot --public`. Этот режим заменяет email в структурированных полях `owner`, `assignee`, `created_by`, `updated_by`, `author` (включая авторов комментариев/связей) и ключах с `email` на `VadimMukabenov`. Значение меняется только если содержит email; обычные имена сохраняются. Обрабатываются вложенные объекты и списки. В manifest записываются `public: true`, число и пути редактирований без исходных email. Checksum и counts вычисляются **после** редактирования.

Оригинальная база остаётся неизменной. Проверка public snapshot сравнивает восстановленную базу именно с очищенными записями: ID, статусы и зависимости сохраняются, email авторства не восстанавливаются. Свободный текст заголовков, описаний и `comment.text` этим флагом не редактируется — это отдельная проверка содержимого перед публикацией. Сырой `.beads/issues.jsonl` в публичный Git не добавляется; сохраняются только проверенные очищенные snapshot-файлы.

Локальный snapshot не означает push на GitHub.

## Восстановление

```bash
scripts/beads-portable restore backups/beads-2026-11-27-01 /tmp/aie-recovered-new
```

Целевой каталог должен **не существовать**, его родитель должен существовать. Скрипт отказывается от существующего каталога, от живого root и его подкаталогов, включая обход через symlink. Он проверяет checksum/формат/ID/полноту зависимостей до создания базы, создаёт отдельный Git-репозиторий, выполняет `bd init --prefix aie --skip-hooks --skip-agents --non-interactive`, проверяет `embedded/aie` и пустоту. Только после этого вызывает import. Живая база никогда не является целью импорта.

После импорта выполняется новый export и сравнение всех экспортируемых полей с учётом документированных исключений ниже. Сравниваются в том числе ID, статусы, поля задачи, тип/направление/metadata зависимости, содержимое/автор/время комментария и memories. Ошибка сравнения означает неуспех, даже если import вернул 0; отдельный каталог остаётся для анализа. Скрипт ничего не удаляет в живом checkout и не переключает его на новую базу.

`verify <snapshot>` делает то же восстановление в уникальном временном каталоге и после проверки удаляет его. Команда удобна перед коммитом и после получения snapshot из Git. Она проверяет именно переданный снимок, не утверждает, что он соответствует более позднему состоянию рабочего tracker.

Выходной каталог restore содержит восстановленный самостоятельный tracker и новый Git-репозиторий, **не копию исходников курса**. Автоматическое объединение с существующим checkout и подмена его `.beads` намеренно не реализованы. Для продолжения работы с восстановленным tracker потребуется отдельный контролируемый перенос исходников/checkout; нельзя поверх живой БД запускать import «для удобства». Это ограничение процедуры, а не обещание восстановления кода, hooks или CI.

## Проверенные границы формата

В Beads 1.0.3 JSONL import сохраняет текущие задачи и содержимое комментариев, но:

- заново генерирует `comment.id`;
- заменяет `dependency.created_by` автором импорта;
- вычисляемые `dependency_count`, `dependent_count`, `comment_count` не являются самостоятельными данными и исключены из сравнения;
- не переносит историю Dolt commits, audit/event history, конфигурацию БД, project ID и credentials. Это логический snapshot текущего состояния, а не побайтовый backup или полная история.

Оригинальные comment IDs/авторы связей остаются в Git JSONL, однако не выдаются за сохранённые внутри восстановленной БД. Неизвестный тип записи, чужой issue-prefix, повторный ID и зависимость на отсутствующую/внешнюю сущность вызывают отказ: текущая программа использует только локальные связи `aie-*`. Расширение на external dependencies требует отдельного проверенного контракта. При ошибке или несовместимости новой версии CLI нельзя автоматически «исправлять» snapshot удалением неудобных полей.

## Фактическая проверка 2026-11-27

В изолированных временных каталогах выполнены:

1. Readonly snapshot реальной базы: **5 задач, 6 зависимостей**; restore сохранил ID, статусы и сравниваемые поля. Readonly export до/после совпал логически, статусы живых задач не менялись этой проверкой.
2. Синтетический round-trip: **3 задачи**, включая закрытую, **2 зависимости** типов parent-child/blocks, **1 комментарий** с кириллицей и **1 memory**. Содержимое и сравниваемые поля сохранились. Fixtures никогда не создавались в живой базе.
3. Wrapper вызван из `/tmp` с намеренно чужими `BEADS_DIR`, DB/server/Dolt/Git/proxy variables: выбран только собственный embedded `aie`.
4. Отвергнуты семь вариантов опасных flags/команд: global, db, server override, init, import, config и file-output override.
5. Restore отказался от существующего назначения, испорченного checksum и пути через symlink внутрь живого репозитория; при плохом checksum целевая база не создавалась.

Это проверка переносимости tracker на установленном CLI. Удалённое сохранение snapshot, восстановление всего курса из GitHub и серверные права этим документом не подтверждаются.

## Дополнительная проверка public snapshot

`--public` проверен на исходной базе: пять email значений owner заменены без изменения ID, статусов и шести зависимостей. Очищенный snapshot успешно прошёл `verify` с созданием отдельной временной БД; исходный readonly export до/после совпал. На отдельном вложенном примере проверены owner/created_by/comment.author/email-варианты, сохранение обычных имён и отсутствие изменения входного объекта.

Дополнительно фактический restore отдельной fixture-задачи с email автора комментария сохранил очищенный комментарий. Проверка отвергла snapshot с `public: true`, оставшимся email в owner и пересчитанным корректным checksum: один public-маркер не принимается как доказательство очистки.

# Проверка проекта observability 0.1.0

Дата: 2026-11-27, Europe/Moscow. Область: только проект архитектуры и определения; не проверка работающей instrumentation.

Независимый агент с чистым контекстом прочитал спецификацию, каталог, текущие `provider.py`/`app.py` Learning Hub и все шесть паспортов. Изменений и модельных операций он не выполнял.

## Существенное замечание и решение

**P2: область переключателя была неоднозначна.** Единственный существующий LLM-вызов выполняется из отдельного CLI; локальный controller Hub не может автоматически запрещать вызовы из других процессов. Первоначальная формулировка также не определяла embeddings.

Исправлено в §11 [спецификации](../superpowers/specs/2026-11-27-observability-and-model-control-design.md):

- Область UI — «Локальный AI в учебной платформе». Все будущие встроенные generation/embedding requests проходят единый admission gate Hub.
- Отдельные CLI/прямой SDK baseline/шесть capstone явно независимы. Для общего режима требуется центральный admission API и учёт in-flight всех клиентов; общий JSON-файл/однопроцессный mutex этого не гарантирует.
- После crash сохранённая policy применяется до допуска запросов; старые операции сверяются, автоматический replay/unload запрещён. `/api/ps` остаётся наблюдением, а не доказательством отсутствия внешних запросов.
- Определение `model-control.disabled_request_escape_count` согласовано с generation/embedding scope Hub.

Других существенных противоречий с паспортами reviewer не обнаружил. Это заключение по документу, не доказательство безопасности или работоспособности будущей реализации.

## Дополнительные проверки автора

- В benchmark знаменатель success включает все назначенные eligible cases, включая admission rejections/ошибки/таймауты; принятые задачи online не подменяют workload.
- 142 уникальных ID; семь профилей с тремя основными метриками; ссылки профилей разрешаются в каталоге.
- Нет фактических значений и фиктивных достижений. Статус всех определений `proposed_not_instrumented`.
- JSON и локальные ссылки проверяются отдельно; `make verify`/`make status` остаются проверкой существующего курса, не внедрения этой спецификации.

Открытые решения для этапа реализации: backup destination, ресурсы полного профиля и итоговые границы retention после измерения объёмов. Это обозначенные проектные параметры, не уже настроенные сервисы.

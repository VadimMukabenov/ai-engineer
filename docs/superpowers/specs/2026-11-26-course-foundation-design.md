# AI Engineer: первый рабочий учебный цикл

## Цель и одобрение

Пользователь одобрил 2026-11-26 реализацию рекомендаций независимого ревью: сохранить полный объём шести проектов, создать канонический план, исследовать вакансии, подготовить диагностику и первый проверяемый учебный цикл. Основной стек Python. Итоговая карьерная цель — полностью удалённая работа от $5000/мес net, желаемо от $10000; РФ в приоритете, Казахстан дополнительный вариант. Срок оффера не обещан.

Этот документ конкретизирует уже одобренный подход; исполнение — в текущей сессии с независимым финальным ревью. Диагностику и самостоятельные задания выполняет ученик: агент подготавливает материалы и платформу, но не проходит их от имени ученика.

## Подход

Выбран монорепо с независимо запускаемыми проектами, отдельным learning-hub и производной сводкой README. Альтернатива «только README» уступает выбранному пользователем интерфейсу курса. Альтернатива «сначала полная LMS» откладывает обучение; выбран первый законченный цикл с дальнейшим расширением без сокращения программы.

## Данные

- `governance/plan.json`: версии, цели, 6 обязательных project ID и 9 module ID, решения/ограничения, рубеж начала откликов.
- `projects/learning-hub/course/catalog.json`: каталог skill ID, модули, предпосылки, результаты, критерии и уроки. Добавление типового урока — данные. Смена модели допускает версионированную миграцию.
- `projects/*/passport.json`: пользователь/сценарий, данные, baseline, уникальные результаты, критерии демонстрации и завершения.
- `learning_records/attempts/*.json` и `learning_records/assessments/*.json`: раздельные неизменяемые записи попыток и решений; оценки ссылаются на попытку, критерий, версию и файлы-доказательства. Первоначально реальных результатов нет.
- `research/market/batches/*.json`: наблюдения первичных вакансий с provenance, датой, обязательностью, gross/net/unknown, ограничениями и отдельным статусом проверки. Неподходящие наблюдения сохраняются с причиной и не становятся подтверждёнными возможностями.
- `.beads/`: отдельная embedded Dolt база aie, никакого соединения с командным tracker. Задачи разработки хранятся здесь, а не в отдельном дублирующем task database.

## Учебные блоки

M00 Engineering Python; M01 Direct LLM API; M02 Core AI Engineering; M03 Evals/observability; M04 resilient backend; M05 search/storage; M06 inference/MLOps; M07 fine-tuning; M08 System Design/FinOps. Фундамент Python, статистики, линейной алгебры, ML/data leakage, токенизации/attention — явные результаты внутри блоков. Переход к первому сценарию не требует окончания всей углублённой программы.

Навыки связываются с несколькими проектами и требованиями рынка. У capstones отдельные результаты: refunds — состояния/HITL/идемпотентность; incident — timeline/гипотезы/логи; contracts — структура/ссылки/риски; SQL — семантика/ограничения/права; recruitment — extraction/provenance/consistency; sales — память/CRM/операции.

## Реализация первого цикла

Python 3.12+, FastAPI, Pydantic v2, Jinja2 и обычные HTML-формы. Это выбор реализации для Python-first приложения без отдельного JS build; возможный будущий frontend имеет тот же API. Окружение learning-hub изолировано и фиксируется uv.lock. Все capstones пока имеют паспорта, а не фиктивные готовые приложения.

Dashboard: курс и прогресс по результатам, отдельные проекты, рынок с ограничениями, текущая диагностика и история попыток. Форма принимает попытку с пометкой помощи и сохраняет файл атомарно. Запись попытки НЕ выставляет зачёт. Перезапуск приложения не теряет попытку. Интерфейс слушает только loopback по умолчанию; сервисы работодателя и реальные персональные данные не используются.

Первый цикл: входная диагностика (без раскрытия эталона), первый урок про Python/HTTP и direct LLM API, лабораторная с TODO ученика и локальным Ollama. Учебные TODO не входят в тесты исправности платформы; их непройденность видна отдельно и не маскируется пропуском тестов. Демонстрационные проверки платформы используют временные фикстуры, не learner records.

## Контроль

`make verify` проверяет схемы, IDs, ссылки, DAG предпосылок, обязательный объём, критерии, записи и hashes evidence. `make test` проверяет реальное поведение, включая неправильные данные и перезапуск. `make status` показывает точный следующий шаг и реальные ограничения. Сводка README и UI вычисляется из одних данных.

Локальный approved-content lock выявляет непреднамеренный drift, но не защищён от владельца файлов. GitHub CI проверяет PR. Фактическую доступность rulesets на публичном репозитории (уточнено пользователем 2026-11-27) и границу прав проверить; если они недоступны или используется admin identity, отразить это как limitation. AGENTS/hooks/второй ИИ не считаются абсолютной защитой.

## Приёмка foundation

1. Новый агент восстанавливает 6 проектов и 9 модулей без чата.
2. Нельзя удалить обязательную тему, поставить зачёт без попытки/evidence или сослаться на неизвестный ID без ошибки проверки.
3. Есть полный первичный реестр наблюдений рынка; unknown и rejected показываются честно. Выборка исследовательская, не статистика всего рынка.
4. Ученик видит диагностику, сохраняет попытку и после перезапуска видит её в истории. Реальное освоение начинается с 0.
5. Все проекты имеют паспорта и отдельный будущий demo contract; первый учебный цикл готов, но не пройден агентом.
6. Код и состояние отдельного Beads сохранены удалённо; восстановление проверено в чистой копии либо явно зафиксирована конкретная недоступность.
7. Нет изменений ядра, VPN, глобального bd, драйверов и системных пакетов; бюджет внешних платных ресурсов пока $0.

## Неуточнённое и измерение

Бюджет API/GPU ожидает ответа; до ответа платные ресурсы не используются. Фактическая диагностика и календарь зависят от попыток ученика. Общая трудоёмкость уточняется после первых занятий; полная программа и шесть capstones остаются в объёме.

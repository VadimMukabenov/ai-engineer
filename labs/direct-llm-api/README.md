# LAB01 · Прямой вызов локальной модели через официальный SDK

Статус: материал готов, реализация ученика отсутствует. `exercise.py` намеренно содержит TODO и `NotImplementedError`. Агент не выполняет лабораторную от имени ученика. Предварительно 2–4 часа после D00/L00; фактическая сложность уточняется по попытке.

Предпосылки: [D00](../../projects/learning-hub/course/materials/D00.md), [L00](../../projects/learning-hub/course/materials/L00.md), разобранные пробелы Python/HTTP из M00. Результаты: O-M01-01, O-M01-02, O-M01-03. Первый вызов выполняется через официальный `openai.AsyncOpenAI`, без LangChain/LangGraph и без самописной HTTP-обёртки вместо SDK.

## Условия

Имеющийся Ollama уже предоставляет локальный OpenAI-совместимый endpoint `http://127.0.0.1:11434/v1`; модель `qwen2.5-coder:7b` уже установлена. Проверять доступность можно, но не изменять Ollama, модели, ядро, VPN, драйверы и системные пакеты. Если сервер или модель недоступны — зафиксировать блокер. Не делать автоматический pull, login, restart или облачный fallback. Бюджет внешних вызовов — $0.

Обязателен local default: только loopback `127.0.0.1`/`localhost`, порт 11434, путь `/v1`, модель из условия. Проверяйте разобранный URL, а не `startswith`: адрес вида `http://127.0.0.1.example.org` не локальный. Запретите userinfo, redirects и использование внешнего proxy транспортом клиента. Настройка endpoint не должна позволять утечку локального фиктивного ключа наружу. Существование ключа или `LLM_CLOUD_ALLOWED=true` не является согласием пользователя на платные вызовы: облачная ветка LAB01 всегда завершается до запроса. Позже профиль провайдера будет включать реальный ключ, отдельное согласование и лимит бюджета без переписывания предметной функции.

## Задача

Напишите обработчик, который извлекает категорию, срочность и краткое содержание синтетической заявки. Конфигурация читается из окружения. Через `AsyncOpenAI` выполните один `await client.chat.completions.create(...)`, получите текст, проверьте его как JSON и провалидируйте предметную модель Pydantic. Передача `response_format` не заменяет проверку результата и допустима только после проверки возможностей локальной версии.

Схему `TicketExtraction` реализуйте самостоятельно:

| Поле | Контракт |
|---|---|
| `category` | Только `billing`, `technical`, `other` |
| `urgency` | Только `low`, `normal`, `high` |
| `summary` | Строка длиной 1–120 символов |
| Лишние поля | Запрещены |

Разделите конфигурацию, создание клиента, модельный запрос и валидацию. Выберите строгую обработку типов и объясните её. Ограничьте timeout, вывод и число повторов; для первого эксперимента `max_retries=0`, чтобы измерения не скрывали несколько запросов. Клиент закрывается при успехе, исключении и отмене. Не сохраняйте содержимое ключа, полный prompt или персональные данные в лог.

До вызова составьте ожидаемые категории/срочность и объяснение для четырёх случаев. Эталона здесь нет: спорный вход обсуждается после вашей попытки.

1. «В счёте за ноябрь вижу две одинаковые строки списания, прошу проверить».
2. «После обновления приложение не открывается у всей команды, работа остановлена».
3. «Где найти описание тарифа для будущего проекта?».
4. «Счёт непонятен и иногда не работает вход» — предложите правило для неоднозначности.

Отдельно проверьте код на искусственно переданных ответах: пустой content; не-JSON; JSON без summary; summary длиннее 120; неизвестная category; лишнее поле. Эти проверки не требуют вызова модели.

## Окружение и запуск

Работайте из корня монорепо в пользовательском uv-окружении. Для этой лабораторной зависимости самостоятельны и не подменяют окружение learning-hub. Создайте собственный `.env` по `.env.example`; не добавляйте реальный ключ в Git. Пример команды после реализации:

```bash
uv run --no-project --env-file labs/direct-llm-api/.env --with openai --with pydantic python labs/direct-llm-api/exercise.py
```

Команда может скачать Python-пакеты из реестра, но не делает платных API-вызовов сама по себе. Зафиксируйте фактические версии Python/OpenAI SDK/Pydantic/uv в отчёте; повторный эксперимент должен использовать те же версии. До заполнения TODO ожидается `NotImplementedError`, а не успешный учебный результат. При отсутствии зависимостей возможна более ранняя ошибка импорта. Не менять CI платформы, чтобы сделать учебную заготовку «зелёной».

## Критерии и доказательства

| Критерий | Что представить |
|---|---|
| Прямой SDK | Код с `AsyncOpenAI`, `await`, Chat Completions и закрытием клиента |
| Локальный бюджет | Отклонение cloud и внешнего endpoint до сетевого обращения; отсутствие fallback |
| Схема | Собственная Pydantic-модель; ожидаемые отказы на каждом из шести искусственных ответов |
| Ошибки | Различимые timeout, connection/API, JSON и schema ошибки, ограниченные retries |
| Реальный эксперимент | Четыре синтетических входа, первоначальные ожидания, фактические ответы, latency и версии |
| Самостоятельность | Сохранённая первая попытка, используемые подсказки/документация, устное объяснение нового входа |

Правильность структуры не доказывает правильность категории. После фиксации ожиданий сравните модель с простым baseline по правилам/ключевым словам на тех же входах; разберите каждый спорный случай, не выдумывайте общий процент «качества». Передайте код, безопасный отчёт и вывод: где ошиблась модель, где ваш код, какой эксперимент нужен дальше.

## Обратная связь, перенос и повторение

Проверяющий сначала называет конкретное нарушение критерия и объясняет механизм. Затем ученик исправляет код и получает новый вход, а не копию готового ответа. Перенесите схему в извлечение события инцидента с `timestamp`, `service`, `symptom`: опишите другой контракт и его отрицательные случаи. В следующем занятии без конспекта восстановите путь запроса и причину различать JSON/схему. Это начало transfer к incident-analyst, а не готовый capstone.
